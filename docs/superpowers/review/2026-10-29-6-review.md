## Findings

### 1. Important — The example forwards its bearer token to cross-origin redirect targets

`post_document` calls the default `urllib.request.urlopen` with an `Authorization` header. Python's default redirect handler preserves that header when following redirects; for a POST, a 302 changes the redirected request to GET but still forwards the header. A loopback reproduction with two separate HTTP servers confirmed the second server received `Bearer synthetic-sentinel` after the first returned a cross-origin 302. A configured endpoint, reverse proxy, or compromised service can therefore redirect the example to another host and disclose the environment token.

**Location:** `docs/examples/standards_pdf_parser.py:145-153`.

**Suggested fix:** Disable redirects for this POST, or implement an explicit same-origin redirect policy that strips credentials whenever the origin changes. Add a test proving a redirect target does not receive the bearer token.

### 2. Minor — The general short-block rule omits the first-block exception

The known-limits page says all blocks under 20 characters merge into the previous segment. The segmenter keeps an undersized first child pending and prepends it to the next adequate child; the parser-author guide correctly calls out that a tiny block at the very start merges into the next one. The two pages therefore give conflicting guidance for a source whose first block is short.

**Location:** `docs/guide/known-limits-and-roadmap.md:51-55`; exception described at `docs/guide/parser-author-guide.md:60-64` and implemented in `smos/ingest/segmenter.py` (`_merge_undersized`).

**Suggested fix:** State the first-block exception on the known-limits page and add a behavior pin for an undersized first block followed by a normal block.

### 3. Minor — The endpoint coverage guard cannot see PATCH operations

`_OPERATION` recognizes only GET, POST, PUT, and DELETE. If an API route is added with PATCH, `test_every_endpoint_is_documented_in_the_guide` will omit it from `mentioned`, so the test can pass while that operation has no guide entry. The current OpenAPI routes use only the four recognized methods, so this is a gap in the guard rather than a present undocumented route.

**Location:** `tests/test_docs_guide.py:11,71-75`.

**Suggested fix:** Parse endpoint references from a structured list or include all supported HTTP methods (and test the parser against a PATCH example) so new operations are checked too.
