# Codex review 9: findings and resolution

Package: `2026-10-30-9-review-package.md` (diff `0900a0e..`). Result: 1 High, 1 Moderate. Authentication, zip member handling and
older-schema migration were examined and found sound (no path accepts an expired, revoked or rotating token; duplicate and
traversal members are rejected; the migration runs on the extracted copy).

## High: an interrupted backup load could delete the original store: FIXED

The safety folder and the swap marker were created before any file was moved. A crash at that point (or `store.close()` raising)
left a marker plus an empty safety folder, and `_restore_safety` deleted every live file first, with nothing to restore. A crash
part-way through the moves had the same effect on files not yet moved.

Fix (`smos/admin/backup.py`): `_restore_safety` now replaces a live file only when its copy really is in the safety folder
(`metadata.db` together with its `-wal`/`-shm` side files, `faiss.index` separately); otherwise the live file is left alone. The
`store.close()` call moved inside the guarded block, so a failing close restores and reports instead of escaping.
Tests (RED then GREEN): `test_crash_right_after_the_marker_never_deletes_the_live_store`,
`test_crash_after_moving_only_some_files_restores_the_originals`, `test_close_failing_at_the_start_of_a_load_keeps_the_original_store`.

## Moderate: a failed pentest shutdown could leave the app and the restart marker disagreeing: FIXED

`disable` switched the app to the live store and set `pentest = False` before closing the throwaway store and removing the marker.
A failure in either left the app writing to the live store while `pentest.json` still existed, so the next start would have opened
the throwaway store and hidden those writes.

Fix (`smos/admin/pentest.py`): the app switches only after the throwaway store is closed and the marker is removed; if either step
fails, the live store just opened is closed again and a working throwaway store is reopened, so "marker exists" and "app uses the
throwaway store" stay the same fact. `enable` was reviewed for the mirror case: the switch is complete before the live store's
close runs, so a failing close is now only logged. Tests: `test_failed_throwaway_close_on_disable_leaves_mode_and_marker_consistent`,
`test_failed_marker_removal_on_disable_restores_the_throwaway`, `test_enable_survives_a_failing_close_of_the_live_store`.
