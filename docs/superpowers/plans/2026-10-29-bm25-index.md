# BM25 Inverted Index, Embedding Threads and Benchmark Error Analytics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline; the Governor's standing choice, and no reviewer subagents: review your own diff after each task). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make keyword search cost depend on matching documents instead of store size, let concurrent queries run in parallel, expose a thread knob for embeddings, and make the benchmark explain its own request errors, all shipped as release 0.3.4.

**Architecture:** `BM25Index` becomes a numpy inverted index with incremental add/remove and a read-write lock, reproducing `BM25Okapi` output exactly (checked against the old class kept as a test oracle). `SMOS_TORCH_THREADS` sets torch threads per calling thread. A thread-safe `ErrorLog` collects failed requests in `httpload`, the runner scans the throwaway server's log, and the report page shows an Errors section.

**Tech Stack:** Python 3.12, numpy, `rank_bm25` (test oracle only), pytest, FastAPI/Jinja templates already in the repo.

**Spec:** `docs/superpowers/specs/2026-10-29-bm25-index-design.md`

## Global Constraints

- Output of `BM25Index.query` equals today's: scores equal within float tolerance, same order, ties by insertion order newest first, zero-score padding newest first up to `k`. Constants `k1 = 1.5`, `b = 0.75`, `epsilon = 0.25`.
- Public methods and signatures of `BM25Index` unchanged: `build(corpus)`, `update(uuid, content)`, `add_batch(docs)`, `remove(uuid)`, `remove_batch(uuids)`, `query(text, k)`. Callers do not change.
- No change to `pyproject.toml`, `Dockerfile`, `compose.yaml`, `models/`, `smos/launcher.py` (no rebuilt image); `rank-bm25` stays a dependency. No new file types under `smos/` other than `.py`/`.html`. No new database migration.
- Benchmark result schema stays 1; the `errors` key is additive and older stored results must still render.
- The error collector never stores request bodies, headers or tokens; every stored message is truncated to 200 characters.
- No benchmark figures, hardware details or report JSON from the target host go into the repository (docs, tests, commit messages).
- Use `rtk proxy python -m pytest <path> -q` to run tests (bare `pytest` may collect nothing). Windows: write files with the Edit/Write tools, not bash heredocs containing backslashes.

## Review Focus

Each line has its test in the named task.

1. Queries that are empty, punctuation-only, contain repeated words, or only words absent from the corpus (Task 1).
2. Re-adding a uuid after removing it, removing an unknown uuid, the same uuid twice inside one `add_batch`, `k = 0` and `k` larger than the store (Tasks 1-2).
3. Tiny corpora where idf is zero or negative (two or three documents, a word in every document) take the slow path and still equal the reference (Task 1).
4. Heavy add/remove churn that triggers compaction keeps document frequencies and insertion-order tie-breaking correct (Task 2).
5. A failed request whose error body is huge, binary or not JSON, a missing or empty server log, and a log with chained tracebacks do not crash the collector or the report (Tasks 6-8).
